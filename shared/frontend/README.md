# Shared frontend

Code that every app imports. The UI kit is imported with `import { Button, TreeView } from "@sn/ui"`
(`ui.ts` is the one entry file; the components live in `elements/` and `compounds/`).

The kit follows the shared rules: library code only, no app business logic, styled with the `theme.css` tokens
(`--line`, `--solid-0..7`), so it follows the theme picked in
`ThemePicker`. No UI string is built in: every label is a prop with an English default.

Each app that imports the kit needs the `react` path mapping in its `tsconfig.json` (see `frontend/tsconfig.json`),
because this folder has no `node_modules` of its own.

## Layout

| Where | What it is |
|---|---|
| `elements/` | components that use no other component of the kit: `Button`, `TextBox`, `Select`, `CheckBox`, `Icon`, `Alert`, `Card` |
| `compounds/` | components built from elements (a compound may import elements, never the other way round): `AuthGate` (`Alert`), `ConfirmModal` (`Button`, `Card`), `LabelTextBox` (`TextBox`), `NumberBox` (`TextBox`, `Button`), `TagBox` (`TextBox`, `Button`), `TabPanel` (`TreeView`), `LanguageSwitcher` (`Select`), `ThemePicker` (`Button`, `Card`, `TextBox`, `Select`), `TreeView` (`Icon`) |
| `ui.ts` | the kit's entry point: re-exports the components, plus the locale hooks. `ThemePicker` and `LanguageSwitcher` are in `compounds/SiteSettings.tsx`: import them as `@sn/compounds/SiteSettings` |
| `api.ts` | the fetch client; kept at the root because every app imports it as `@sn/api` |
| `lib/theme.css` | the design tokens; eight apps import it as `@sn/lib/theme.css` |
| `lib/i18n.tsx` | locale context and hooks (`LocaleProvider`, `useTranslation`); bundles are passed in, none ship here |
| `lib/cssVars.ts` | theme tokens with fallbacks, for components that must look right in apps that do not load `theme.css` |
| `lib/theme.ts`, `lib/colorEngine.ts` | one color in, the whole token set out (pure functions, no React) |
| `lib/apps.ts` | the app list; generated by `shared/infra/generate_infra.py` |
| `lib/nav.ts` | `NAV_NODES` (home, account and every app, as `TreeView` nodes) and `isActivePath` |
| `lib/base.css` | the reset every app shares (center started it): box-sizing, headings and lists without browser styles, `[hidden]`, `.sr-only` |
| `lib/useSession.ts` | `useSession()`: loading, then signed in, signed out, or an error when the server is unreachable. It was copied into six apps before |

## Color rule

Only two color names exist. `ThemePicker` takes a solid color and a number of colors and sets them on `<html>`:

- **`--solid-0..7`** (solid-color: `background-color`, `fill`): `--solid-0` is the picked color (the page color); the
  others are `count - 1` more of the same luminance, so they all have the same contrast with `--line`.
- **`--line`** (line-color: `color`, borders, outline, text-decoration, caret, column-rule, stroke, shadows,
  `accent-color`, `scrollbar-color`…): black or white, whichever contrasts more with the solid color.

Softer shades are mixes of `--line`, never new names: `color-mix(in srgb, var(--line) 30%, transparent)` for borders,
75% for muted text, 8% for a tinted panel (`LINE_SOFT`, `SURFACE_TINT` in `lib/cssVars.ts`). An error is
therefore not red: it is told apart by its text and role, not by hue. `--bg`, `--fg`, `--surface`, `--border`,
`--muted`, `--accent`, `--danger` no longer exist.

## Glow

Panels and cards share one shadow, `GLOW` in `lib/cssVars.ts`: `0 2px 16px 0 var(--line)`, a soft glow in the line color
(the same color as a border). `Card`, the `TreeView` drop-down, `.card` in `theme.css`, center's `.shadow` helper, and the face and werewolf panels use it. ChatWork's text shadow follows `--line` too.

## Site tools

`complex/SiteTools.tsx` is the language switcher (Tiếng Việt, English) and the theme picker, together. Every app has it:
`center` and `chat` put it in the `trailing` slot of the navigation bar (`<SiteTools inline />`), the other apps
float it at the top right (`<SiteTools />`). The chosen language is saved in `localStorage["sn_locale"]` (shared by all
apps), sets `<html lang>`, and is read by `useTranslation`. It lives in `complex/` because it is made of two compounds,
and compounds are made of elements only. The apps' texts are still Vietnamese: the switcher sets the language, a
screen starts to follow it when it reads its texts through `useTranslation`.

## Button effects

Every button in every app is the `Button` element (`import Button from "@sn/elements/Button"`): the apps' own `<button>`
tags were replaced, a class such as `secondary` or `danger` (or center's `SECONDARY_BUTTON`, `DANGER_BUTTON`,
`LINK_BUTTON`) became its `variant`. There is no raw `<button>` left in the apps. The buttons of `TreeView` (a parent entry, a toggle, an entry without a link) are `Button` ghost. `primary` has no inline style: its look is the zero-specificity default of `lib/button.css`, so a class
may restyle it (a selected tab, a tile).

`<Button effect="…" status="…">` (styled by `lib/button.css`, imported by `theme.css` and by the `layout.tsx` of center,
chat and work). Colors are only `--line` and `--solid-0..4`; everything stops under `prefers-reduced-motion`.

- **No border.** A button has no border and no outline except the focus ring; it is told apart from the page by its
  fill alone. (`draw` is the one exception: it draws its own 2px border.)
- Fills: `--solid-1` (primary), `--solid-2` (secondary), `--solid-3` (danger); ghost is transparent. Text is `--line`.
  `danger` is not red and has no special border: only its fill differs.
- Glassy: every filled button has a gradient highlight (bright top half, soft bottom) made from `--solid-0`, plus a 1px
  light edge at the top; ghost buttons have neither.
- `effect` is the hover: `invert` (default; swaps fill and text), `tone` (fill moves to `--solid-4`), `sweep` (a layer
  slides in), `draw` (border drawn around, Chrome and Edge only; others jump), `underline`, `slide` (gradient between
  solids), `lift` (rises with a shadow), `hard` (solid shadow that closes when pressed), `ripple` (circle from the pointer).
  Secondary and ghost buttons tint instead of inverting.
- `status="error"` shakes once, `status="success"` bounces once.
- Always: `:active` scales to 0.97, `:focus-visible` draws a 3px `--line` ring, `loading` shows a spinner.

`lib/plainButton.css` (imported by `theme.css` and the layouts of center, chat and work) gives buttons that are not the
`Button` element the same invert hover and press.

## Other controls

`lib/controls.css` (same imports) gives the rest one look: fields get a hover border and a 3px `--line` focus ring,
checkboxes, radios, ranges and `progress` take `--line` as `accent-color`, links get an underline that darkens on hover,
and messages, drop-downs and dialogs fade in. `--line` only; all of it stops under `prefers-reduced-motion`.

## No Tailwind

No app uses Tailwind. `center` styles itself with `app/globals.css` (the two color names) and `app/center.css` (a small
reset plus the layout helpers its pages use: spacing, flex, text sizes, `bg-line`, `text-solid`…).

## Navigation

`TreeView` is the one navigation component. Give it `NAV_NODES` and it draws the main menu of the whole site:

- `orientation="horizontal"` is a top bar: `brand`, the entries in a row, `trailing` pushed to the right. A node with
  `children` opens them in a drop-down (one at a time; Escape, a press outside or following a link closes it).
- `orientation="vertical"` (default) is an indented tree whose parents expand and collapse; a parent that holds the
  current page opens by itself. Icons (`node.icon`, the name of an `Icon`) show in this layout only.
- A node with an `href` is a real link and the one for the current page gets `aria-current="page"`; a node without
  one is a button that calls `onSelect(key)`.
- `activeHref` is the path of the current page. Leave it out and the tree reads `window.location.pathname` after
  mount, which includes an app's basePath (`chat` does this). `center` passes Next's `usePathname()` so the
  link follows client-side navigation.
- With `aria-label` the tree is wrapped in a `<nav>` landmark.
- A link may carry a hash (`/page#part`): it is current only while that hash is current, so two views of one page
  are told apart (`isActivePath` in `lib/nav.ts`). `followLocation` makes the tree follow `window.location` after
  mount, hash changes and Back/Forward included; `activeHref` is then only what the server renders.
- A node with `exact: true` is current only on its own page, not on the pages below it (a section's start page, such as
  `/market`, next to `/market/cart`).

`NAV_NODES` is one flat list, one entry for each page of `MENU` (generated by `shared/infra/generate_infra.py`, in the order of that list: Chat, Market,
Jobs, Werewolf, Face, File, Database), with no groups. An app that is not generated has no entry.

`center` draws its bar in `app/components/AppNav.tsx` and `chat` in `app/chat/ChatNav.tsx` (both client components
that read the route with `usePathname()`, so the active link is right on the first paint and follows client-side
navigation; `chat` puts its basePath back in front). `SiteTools` is in the `trailing` slot. Below 640px the bar turns
vertical (`collapseBelow`): a menu button shows the entries in a column.

Under that bar `chat` keeps the chat's own row (`chat/components/NavBar`: avatar, account button, Hide/Show); the
work pages have none, except that an admin gets a Calls button. The app uses the same look as center (`base.css`,
`theme.css`); the old ChatWork's random color theme and its gradient buttons are gone.

## Reuse inside the kit

Components build on `Button`, `TextBox`, `Select` and `Icon` instead of drawing their own buttons and fields, so the
look, `disabled` and the other attributes stay the same everywhere. `Button` also takes a `ref` (React 19 passes it
as a normal prop). Raw form tags remain only where an element cannot
fit: the element files themselves and the entries of `TreeView`,
whose links and buttons share one hover and active style that a `Button`'s inline style would override.

## Still app-specific on purpose

- `werewolf/Toast`: it can be closed by the user; `Alert` does not offer that yet.
- The 55 `<p className="error">` messages in the apps: replacing them with `Alert` is mechanical but touches almost every page.

## Not moved

- AppCity `ThemePicker`: replaced by `compounds/SiteSettings.tsx` here, which writes this repo's tokens.
- blueskyartist `ListingCard`, `ListingEditForm`, `DataField`, `Sidebar`, `SignIn`, `CustomGoogleSignInButton`,
  `UserCard`, `UserEditForm`, `LanguageSwitcher`, `Icon`: tied to listings, Cognito or its own contexts
  (a shared kit may not hold business logic), or already covered by the AppCity equivalents above.
- blueskyartist `AudioRecord`, `VideoRecord`: `center` already has newer versions built on `useMediaRecorder`.

## Dropped on purpose

- `SubmitButton`, `FormActions`: `<Button type="submit" loading loadingLabel="Sending…">` and a second `Button variant="secondary"` do the same.
- `ArrayView` (with its table and grid views) and `SiteNav`: `SiteNav` was its only user, and `TreeView` now draws the
  navigation.

## Differences from the originals

- The per-mount random accent colors of AppCity are gone; components use theme tokens.
- `SplitPanel` keeps the sizes (as weights) in state, so a second drag starts where the first ended and a pane that is hidden and shown again has its old share.
- `NumberBox` arrows respect `min` and `max`.
- `ConfirmModal`, `LabelTextBox` and `TagBox` have proper roles and label association.

## GalleryView

`compounds/GalleryView.tsx`: the business-side page of one table as a grid of cards, built from the same API as `CrudView`
(`GET <api>/tables`, `GET <api>/<table>?q&offset&limit` -> `{total, rows, labels?}`, POST/PATCH/DELETE, column `media`/`ref`,
table `create_via`). Props: `api`, `table`, `config`. Search, filter chips, sort, "Load more" (offset paging),
Add (the shared `CrudRowForm`, or `UploadDialog` for a `create_via` table), Edit and Delete gated exactly like `CrudView`.

| `config` key | Meaning |
|---|---|
| `title` | column used as the card title (required) |
| `subtitle` | column or columns under the title |
| `badge` | status-like column drawn as a colored pill |
| `image` | media column: thumbnail on top (`media.preview`), icon by kind as fallback, click opens the larger preview |
| `body` | long text column, clamped to 3 lines |
| `meta` | small columns (dates, counts, refs) written with the `CellView` rules |
| `filters` | columns offered as chips; values from `GET <api>/<table>/suggest?column=&q=&limit=20` (none shown on error) |
| `sort` | `[{column, label}]`, sent as `sort=<column>` |
| `pageSize`, `cardMinWidth`, `emptyText` | 24, 220, translated default |

Chosen filters are sent as `filter_<column>=<value>`. Example (`frontend/app/market/shop/page.tsx`):

```tsx
<GalleryView api="/api/market/data" table="market_products"
  config={{ title: "name", badge: "category", body: "description", meta: ["created_at", "price_cents"],
            sort: [{ column: "created_at", label: "Newest" }], filters: ["category"] }} />
```
